# 데이터 검증 및 포매팅 규칙

## 1. 개요
본 문서는 시스템에 입력되는 PDF 파일의 무결성을 확인하고, OCR 엔진을 통해 추출된 원시 데이터를 시스템이 요구하는 규격에 맞게 정제, 보정, 검증하는 규칙을 정의합니다. `src/utils/validators.py` 및 `src/utils/formatters.py`에 구현된 핵심 로직을 포함합니다.

## 2. 입력 파일 검증
`src/core/pdf_loader.py` 단계에서 시스템의 안정성을 확보하기 위해 수행되는 사전 검증 규칙입니다. (FUNC-001, FUNC-002)

* **파일 형식 및 상태 검증:**
  * **확장자:** `.pdf` 파일만 허용.
  * **용량 제한:** 개별 파일 최대 300MB 이하.
  * **동시 처리:** 1회 최대 10개의 PDF 파일 입력 허용.
  * **보안:** 비밀번호가 설정되어 암호화된 PDF는 처리를 제한하고 에러 반환.
  * **페이지 수:** 3페이지 미만의 PDF는 금융거래조회서의 기본 규격을 충족하지 못하므로 입력 제한.
* **파일명 파싱 규칙:**
  * 업로드된 파일의 이름에서 `감사대상회사`, `조회처`, `조회처 유형`을 자동 추출.
  * 지정된 파일명 명명 규칙에 어긋나는 경우 `ValueError` 예외를 발생시키고 해당 파일 처리를 건너뜀.

## 3. 텍스트 보정 및 포매팅 규칙
OCR이 인식한 텍스트를 `Sample.csv`에 정의된 데이터 타입에 맞게 변환하고, 오인식된 문자를 교정합니다. (REQ-F-005)

### 3.1. 유사 문자 보정
특정 필드(숫자 전용 필드, 날짜, 계좌번호 등)에서 문맥상 명확한 OCR 오인식을 자동으로 교정합니다.
* 알파벳 대문자 `O` 또는 소문자 `o` -> 숫자 `0`
* 알파벳 대문자 `I`, 소문자 `l` -> 숫자 `1`

### 3.2. 데이터 타입별 정제
| 데이터 타입 | 검증 및 정제 규칙 |
| :--- | :--- |
| **INT (금액/수량)** | 문자열에서 숫자와 쉼표(,)만 추출. 필요시 정수형 캐스팅. | |
| **통화** | 금액 숫자와 통화 단위(KRW, USD, JPY 등)를 분리 혹은 결합 검증. |
| **FLOAT (이율)** | 소수점 이상의 문자 제거, 숫자와 `%` 기호 추출. (예: `3.60%`) |
| **날짜 (YY.MM.DD)** | 연, 월, 일 패턴 정규식 매칭. 날짜 필드 내부에 섞인 불필요한 단어(예: 템플릿에 인쇄된 '수표', '어음')는 제거.
| **계좌/일련번호** | 숫자와 하이픈(-) 패턴 검증. 하이픈이 누락되거나 잘못 인식된 경우 복원 시도. |

## 4. 논리적 검증 및 예외 처리

### 4.1. 공란 유지 정책
* **규칙:** 금융거래조회서의 특성상(예: 대출 잔액 없음, 인출 제한 없음 등) 의도적으로 비워둔 셀이 존재합니다. 시스템은 이를 누락이나 오류로 판단하지 않고 `None` 혹은 `Null` 값으로 정상 유지합니다. (REQ-F-004)

### 4.2. 불필요한 텍스트 배제
표의 테두리 바깥이나 안쪽에 세로로 인쇄된 특정 안내 문구는 표 데이터 추출 시 혼선을 주므로 명시적으로 제거합니다.
* **제거 대상 키워드:** `전자어음`, `수표·어음`, `미결제 전자어음`

### 4.3. 합계 검증 배제 정책
* **규칙:** 시스템은 추출된 데이터(예: 개별 대출금액)의 합산 로직을 수행하여 원본의 '총계'와 대조·교정하지 않습니다.
* **사유:** 시스템의 목표는 '문서에 적힌 내용을 그대로 정확히 추출(Key-in 자동화)'하는 것이며, 원본 문서 자체의 오류(합계 불일치 등)를 판단하고 수정하는 것은 회계사의 고유 업무 영역으로 둡니다.
