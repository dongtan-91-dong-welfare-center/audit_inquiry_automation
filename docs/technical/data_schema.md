# 데이터 사전 및 인터페이스 정의서

## 1. 개요

본 문서는 금융거래조회서(은행조회서 기준)에서 추출해야 할 항목별 데이터 규격, 공통 자료형, 예외 처리 규칙 및 컴포넌트 간 데이터 전달 인터페이스를 정의합니다. 이를 통해 OCR 추출 데이터가 최종 엑셀 템플릿에 매핑되는 기준을 명확히 합니다.

## 2. 공통 데이터 자료형

시스템 내부(`validators.py`, `formatters.py`)에서 텍스트를 정제하고 검증할 때 사용하는 기본 자료형 규격입니다.

| 데이터 타입 | 포맷 및 정제 규칙 | 예시 |
| --- | --- | --- |
| **INT** | 쉼표(,)가 포함된 숫자열. 문자가 섞인 경우 숫자만 추출 | `1,000,000` |
| **INT + Currency** | 숫자와 통화 단위(KRW, USD, JPY) 결합 | `1,000,000 KRW` |
| **FLOAT + %** | 소수점이 포함된 숫자와 `%` 기호 결합 | `3.60%` |
| **YY.MM.DD** | 연(2자리), 월, 일 형태의 날짜 | `24.12.31` |
| **YYYY.MM.DD ~** | 시작일과 종료일을 틸드(`~`)로 구분하는 기간 형식 | `2024.12.31. ~ 2025.12.31` |
| **ENUM** | 사전 정의된 선택지 중 하나로 매핑 | `예금`, `KRW`, `만기일시` |
| **VARCHAR** | 일반 텍스트 (길이 가변) | `(주)삼성전자` |
| **계좌/일련번호** | 숫자와 하이픈(-) 조합. (유사 문자 O/0, I/1 보정 대상) | `352-1244-7439-83` |

## 3. 은행조회서 항목별 데이터 스키마

조회서 내의 각 표는 고유한 '앵커(시작 문장)'를 기준으로 식별되며, `Sample.csv`에 정의된 규격에 따라 데이터를 추출합니다.

### 3.1. 제 1~2항: 금융상품 및 대출 거래

* **1. 금융상품 앵커:** `1. 조회기준일 현재 조회대상회의사의 당 은행에 대한 금융상품의 내용은 다음과 같습니다.`
* **2. 대출거래 앵커:** `2. 조회기준일 현재 조회대상회사에 대한 당은행의 대출 거래의 내용은 다음과 같습니다.`

| 표 항목 | 주요 필드 | 필수(Y/N) | 타입 | 비고 / 매핑 규칙 |
| --- | --- | --- | --- | --- |
| **1. 금융상품** | 금융상품 종류 | Y | ENUM | 예금, 적금, 예·적금 |
|  | 계좌번호, 금액, 연이자율 | Y | 규격 참조 |  |
|  | 최종이자 지급일, 만기일 | Y | YY.MM.DD |  |
|  | 인출제한 등 | N | VARCHAR | 빈칸 허용 (공란 처리 유지) |
| **2. 대출거래** | 대출종류 | Y | ENUM | 단기, 장기 |
|  | 금액 (약정한도액 / 대출금액) | Y | INT | 금액 하위 속성 분리 |
|  | 대출일, 최종만기일, 최종이자지급일 | Y | YY.MM.DD |  |
|  | 연이자율 | Y | FLOAT + % | 이자 하위 속성 |
|  | 상환방법 | Y | ENUM | 만기일시, 원리금상환 |
|  | 담보·보증 및 관련약정 | N | VARCHAR | 빈칸 허용 |

### 3.2. 제 3~5항: 보증, 약정, 파생상품 및 연대보증

* **특수 매핑 규칙 적용 구간:** 병합된 셀이나 계단식 레이아웃을 처리합니다.

| 표 항목 | 주요 필드 | 특이사항 (구조 및 파싱 규칙) |
| --- | --- | --- |
| **3. 지급보증 및 약정** | 내용, 한도액, 실행금액 등 | '내용' 열은 다른 열과 독립적인 높이를 가짐. 해당 셀에서 추출한 값을 다른 모든 하위 행 데이터에 일괄 적용함. |
| **4. 파생상품계약** | 계약 종류, 한도액, 평가금액 등 | (추가 개발 필요 항목) |
| **5. 타법인 연대보증** | 내용, 대상회사/여신, 한도, 자산 | '내용' 열 하위에 다른 속성들이 계단식으로 존재. 동일한 Row로 취급하지 않도록 Y좌표 기반 그룹화 로직 보정 필요. |

### 3.3. 제 6~9항: 어음·수표 교부 및 담보 제공 내역

* **특수 텍스트 무시 규칙:** 셀의 테두리 바깥이나 안쪽에 세로로 인쇄된 앵커 텍스트를 추출에서 제외해야 합니다.

| 표 항목 | 특이사항 및 세로 텍스트 무시 규칙                                                                         |
| --- |---------------------------------------------------------------------------------------------|
| **6. 어음·수표 교부** | - 셀 좌측에 세로로 쓰인 `전자어음`, `수표·어음` 텍스트는 무시. <br> - 템플릿에 인쇄된 '수표', '어음' 단어는 제거하고 순수 날짜/일련번호만 추출. |
| **7. 미결제 어음·수표** | - 셀 좌측 세로 텍스트 `미결제 전자어음`, `수표·어음` 무시 적용.                                                    |
| **8. 보관 어음·수표** | 구분, 번호, 금액, 발행일자 등 (추가 개발 필요 항목)                                                            |
| **9. 담보·보증 제공** | - '구분' 열의 값은 해당 표의 모든 행에 공통 적용. <br> - 주요 필드: 소유자, 감정금액, 설정금액, 순위 등 정수 및 통화 타입 강제 검증. |

## 4. 컴포넌트 간 데이터 인터페이스

각 파이프라인 단계를 거치며 데이터는 다음과 같은 규격으로 변환 및 전달됩니다.

### 4.1. OCR Engine -> Postprocessor (`List[Tuple]`)

특정 프레임워크(PaddleOCR 등)에 종속되지 않도록 통일된 Raw 형태 (ADR-008).

```python
[
    ("예금", [x1, y1, x2, y2], 0.98), # [텍스트, Bounding_Box_좌표, 신뢰도]
    ("352-1244-7439-83", [x1, y1, x2, y2], 0.95),
    ...
]

```

### 4.2. Postprocessor -> Excel Builder (`Dict[str, List[Dict]]`)

좌표 기반 행/열 정렬과 다중 페이지 병합(ADR-007)이 완료된 구조화 데이터. 추출할 수 없는 공란은 `None`으로 전달하여 요구사항(REQ-F-004)을 충족합니다.

```python
{
    "1.금융상품": [
        {"금융상품의 종류": "예금", "계좌번호": "352-1244-7439-83", "금액": "350,000 KRW", "인출제한 등": None},
        ...
    ],
    "2.대출거래": [
        {"대출종류": "단기", "금액_약정한도액": 1000000, "상환방법": "만기일시", ...}
    ]
}

```

### 4.3. Excel Builder 최종 출력 (`.xlsx`)

위의 딕셔너리 데이터는 `조회처 유형` (예: 은행)에 따라 사전에 정의된 `template_은행.xlsx` 내의 해당 시트(Sheet) 혹은 `.csv` 템플릿(`1.금융상품.csv`, `2.대출거래.csv` 등)의 셀 위치에 매핑되어 최종 파일로 생성됩니다.
